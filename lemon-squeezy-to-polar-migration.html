1. Endpoint & Parameter Mapping: Lemon Squeezy → Polar.sh

Polar.sh exposes unauthenticated Customer Portal license endpoints that only require your public organization_id (UUID) — so you never embed a secret API token inside your extension bundle.

Activate POST /v1/licenses/activate POST /v1/customer-portal/license-keys/activate
Validate POST /v1/licenses/validate POST /v1/customer-portal/license-keys/validate

Content-Type application/x-www-form-urlencoded application/json

Tier / Product lock Checked in response metadata benefit_id (optional UUIDv4; strongly recommended if selling multiple tiers/extensions)

2. Activate vs. Validate (TypeScript MV3 Pattern)

You only need to call /activate if your Polar license key benefit enforces a device activation limit (e.g., max 3 devices). Otherwise you can call /validate directly without an activation_id. 

// 1. Activate a device slot (required when activation limits are enabled)
const activateRes = await fetch(
  'https://api.polar.sh/v1/customer-portal/license-keys/activate',
  {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      key: licenseKey,
      organization_id: POLAR_PUBLIC_ORG_ID,
      benefit_id: EXPECTED_PRO_BENEFIT_ID, // prevents cross-product key reuse
      label: `Chrome Extension – ${deviceId}`,
    }),
  },
);
const activation = await activateRes.json();

// 2. Validate on startup / daily chrome.alarms schedule
const validateRes = await fetch(
  'https://api.polar.sh/v1/customer-portal/license-keys/validate',
  {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      key: licenseKey,
      organization_id: POLAR_PUBLIC_ORG_ID,
      benefit_id: EXPECTED_PRO_BENEFIT_ID,
      ...(activationId ? { activation_id: activationId } : {}),
    }),
  },
);
const data = await validateRes.json();

Remember to declare Polar's API origins in your MV3 manifest.json:

"host_permissions": [
  "https://api.polar.sh/*",
  "https://sandbox-api.polar.sh/*"
]

3. Five MV3 + Polar Gotchas That Break in Production

  1. Per-minute IP rate limits (HTTP 429 with retry-after: ~41s): Never validate on every popup open. Persist license state in chrome.storage.local (Service Worker globals vanish after ~30 seconds), revalidate daily via chrome.alarms, and keep Pro unlocked during transient network / 429 / 5xx failures inside a 72-hour offline grace window.
  2. Monotonic backwards-clock tamper guard: A naive Date.now() - lastValidatedAt < 72h check stays valid forever if a user rolls their OS clock backward. Reject grace access whenever now + 60_000 < lastValidatedAt.
  3. Check status vs. expires_at by billing model: For subscriptions, check data.status === 'granted' (Polar flips it to revoked/disabled on cancel or refund). For one-time keys with fixed validity, check both status === 'granted' and expires_at.
  4. activeTab fails from Chrome Side Panel buttons: Clicking a button inside Chrome's sidePanel does not reliably grant activeTab to the underlying webpage. Use tabs + scoped host_permissions. For Firefox MV3, strip sidePanel, map side_panel → sidebar_action, use background.scripts, and declare browser_specific_settings.gecko.
  5. Migrating existing Lemon Squeezy buyers via $0 checkout: Export your LS customer, order, and key CSVs early. Verified live on sandbox.polar.sh: applying a 100% off discount drops checkout to $0, hides the credit card form completely, and immediately issues a fresh Polar key. For larger customer lists, run a local one-off script calling POST /v1/discounts/ (basis_points: 10000, max_redemptions: 1, ends_at) using a local token with discounts:write — never bundle that token in your extension. (Note: PayPal subscriptions on Lemon Squeezy cannot migrate automatically.)

4. Honest Security Tradeoff (Client-Side Bypass)

Any purely client-side license check inside a browser extension can be bypassed locally with DevTools. Zero-backend Polar validation is an intentional engineering tradeoff for $5–$29 local utility extensions where your marginal server cost per user is $0. If your extension proxies paid LLM APIs or proprietary backend databases, validate the Polar license key on your backend server before forwarding paid requests.
